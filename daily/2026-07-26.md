# 2026-07-26｜Week 3：调研 Monad 上的 Chainlink Live Data 路径

## 今日问题

为了继续验证 BTC/USD 15 分钟预测方向，我调研了 Chainlink Data Streams（Live Data）能否在 Monad 上提供低延迟、可链上验证的 BTC/USD 价格。

目标不是直接相信网页中的价格，而是确认完整路径能否成立：

```text
签名价格报告 → 链上 Verifier 验证 → 合约读取并按时间窗结算
```

## 结论

### Monad Testnet：当前不能作为可运行依赖

Chainlink 的 Supported Networks 文档仍列出了 Monad Testnet 的 Verifier Proxy：

- `0xC539169910DE08D237Df0d73BcDa9074c787A4a1`

但我通过 Monad Testnet RPC（Chain ID `10143`）实时检查该地址，`eth_getCode` 返回 `0x`，即没有部署合约代码。因此目前不能在 Monad Testnet 上验证 Data Streams report，也不能把文档地址直接当成可用基础设施。

### Monad Mainnet：技术路径存在

Monad Mainnet（Chain ID `143`）的 Data Streams Verifier Proxy 为：

- `0xEd813D895457907399E41D36Ec0bE103E32148c8`

该地址实际有 `7,009 bytes` bytecode，且 `s_feeManager()` 当前返回零地址。这里的零地址只说明当前没有链上 FeeManager 路径，并不表示 Data Streams API 免费。

## Data Streams 的实际调用方式

它不是 `latestRoundData()` 式的固定 Push Feed，而是 Pull Oracle：

1. 后端用 Chainlink Data Streams 的 HMAC API 凭据请求最新签名 report；
2. 将未改写的 report payload 放进开盘或结算交易；
3. 合约调用 Verifier Proxy 的 `verify(payload, parameterPayload)`；
4. 链上验证 DON 签名后解码 Crypto Report Schema v3；
5. 合约检查 `feedId`、`observationsTimestamp`、`expiresAt`、正价格和价格精度，再记录可结算价格。

因此后端只能负责取回签名报告，不能成为价格真相来源；最终价格必须由合约验证。

## 对 BTC 15 分钟 Round 的启发

开盘和结算不能简单读“当前最新价”，而要约束 report 所属时间窗口：

- 开盘：Round 开始后第一个合格 report；
- 封盘：结束前停止下注；
- 结算：结束后宽限窗口中的第一个合格 report；
- 无合格 report：取消该 Round 并退款。

合约至少需要拒绝错误 `feedId`、过期 report、窗口外时间戳和非正价格。
