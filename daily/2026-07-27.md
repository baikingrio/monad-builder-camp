# 2026-07-27｜Week 3：将 BTC 概率市场收敛为 Single-Lane Target Sprint

## 今日目标

今天继续收敛 Monad Probability Exchange 的 Hackathon MVP。重点不是继续堆叠交易所功能，而是确认第一版到底要验证什么、哪些机制必须真实上链、哪些功能必须暂缓。

最终将方案整理为 **BTC Target Sprint v0.5**：一个在 Monad Testnet 上每 15 分钟连续换场的 BTC/USD 固定目标价二元市场。

## 产品收敛

第一版不再尝试多个并行的 Rolling Market、Probability Ribbon 或真实订单簿，而是只开放一个正在交易的市场：

```text
BTC/USD 在指定时间是否会达到或高于 Target Price？
```

用户优先看到：

- 固定 Target Price；
- Pyth Live Reference；
- 当前价格距目标的金额与百分比；
- 倒计时；
- Above / Below 的市场隐含报价；
- 交易金额、滑点、手续费和可验证 Proof。

界面可以采用交易终端风格，但不会伪装成 CLOB 或真实用户订单簿。深度区域只展示 AMM 的 `Liquidity Ladder / Quote Depth`，说明不同交易规模下的预估执行价格和 Price Impact。

## Single-Lane Continuous Rollover

产品的核心机制改为单通道连续换场：

```text
Round #101 到期
→ Pyth 边界报告结算 #101
→ 同一价格成为 #102 的 Target Price
→ #102 开放交易
```

这保留了持续运行的市场体验，但不会同时维护多个市场、分散 Test USDC 流动性或引入 Rolling Probability Ribbon 的解释负担。

需要特别保持两类资金隔离：

```text
上一轮 redeemableCollateral：只用于上一轮持仓用户的赎回
下一轮 initial liquidity：只能来自独立的协议 Testnet Treasury
```

不能在 Rollover 中复用或挪用上一轮的可赎回抵押品。

## Oracle 结算规则

我重新核对了 Pyth `parsePriceFeedUpdatesUnique` 的官方说明。该方法可以返回指定时间范围内的第一条更新，并保证不存在更早且仍在该范围内的合格更新。

因此 v0.5 将结算定义为：

```text
使用 expiryTime 之后第一条有效 Pyth BTC/USD 报告结算。
```

在 Rollover 中，同一份已解析的边界报告应被复用：

```text
currentSettlementPrice == nextTargetPrice
currentSettlementPublishTime == nextAnchorPublishTime
```

实际实现前仍需要在 Monad Testnet 上专项测试多份 `updateData`、不同 `publishTime`、边界窗口、重复提交和不同调用者 payload，确认任意调用者不能靠选择报告改变市场结果。

## Outcome Share 与 Sell Gate

MVP 采用合约内部余额：

```solidity
mapping(address => uint256) aboveBalance;
mapping(address => uint256) belowBalance;
```

第一版不发行 ERC-20 或 ERC-1155 Outcome Token，也不支持钱包间自由转账。

Buy、Settlement、Void 和 Redeem 是必须完成的真实闭环。Sell 是条件功能：只有在 TypeScript 模拟器完成至少 10,000 次随机 Buy / Sell / Settle / Void / Redeem 序列，并通过偿付能力、手续费、舍入和无风险套利 Gate 后，才会进入 Solidity 与前端范围。

如果 Sell 未通过 Gate，Demo 会如实保留：

```text
Buy → Hold → Settle / Void → Redeem
```

## 下一步

开发顺序固定为：

```text
Phase 0：离线经济模型与不变量
→ Gate 0：决定 Sell 是否启用
→ Phase 1：单市场 Buy / Pyth Settlement / Void / Redeem
→ Gate 1：Pyth 唯一结算验证
→ Phase 2：Single-Lane Rollover
→ Phase 3：Terminal
→ Phase 4：Testnet 用户试用
```
