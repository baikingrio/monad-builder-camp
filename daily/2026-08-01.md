## 前端：结算反馈与下一轮交接

今天同步的前端更新重点不再只是展示订单簿，而是补齐短周期市场的真实用户闭环：

```text
关闭交易
→ 等待链上确认
→ 展示个人化结果与可领取金额
→ 新轮 ready 后自动切换
→ 上一轮未领取资产仍可直接赎回
```

新增或加固的体验包括：

```text
T=0 立即冻结新下单和交易入口
+ Closing / Resolving / Resolved / Preparing-next 状态机
+ 最终 Settlement Price 图表标注
+ 结算后胜 / 负 / Void / 无仓 / 未连接的钱包状态
+ 上一轮结果条 PreviousRoundResultBar
+ 跨轮 Redeem CTA
+ 新轮 Ready Gate 与自动切轮
+ 用户手动查看历史轮时不被自动切换覆盖
+ Order Ticket 的订单状态提示
+ 价格图表缩放与边缘价格显示优化
```

自动切换到新一轮后，若用户在上一轮仍有可领取资产，页面不会强制“先领取才能继续交易”；而是保留结果条和领取入口，使用户能继续交易，也能随时完成旧轮赎回。

Nuxt 的测试前置条件也被明确下来：新环境执行 Vitest 前必须先运行：

```bash
pnpm exec nuxi prepare
```

它会生成 `.nuxt/tsconfig.json`。若缺少这一步，Vitest 会在 TypeScript 配置解析阶段失败，并不代表业务测试失败。

## 真实订单簿的展示边界

Pyth 实时价格只作为 Reference Price；订单簿成交价由真实用户订单决定。

在没有对应盘口时，前端可以给用户提供基于 Reference Price 和 Target 的交易估算，但它只能标为估算，不得伪装成：

```text
真实盘口
真实成交价
可保证成交的流动性
```

市场 Target、结算结果和资金状态仍以 Monad 链上合约验证的 Pyth 价格证明为准。
