## ZeroDev 交易账户：从方案进入前端运行时

前端现在接入了 ZeroDev Kernel、Permission / Session、预检、Paymaster 配置边界与交易账户状态等运行时模块，并新增相关单元测试。

产品目标保持为：

```text
首次启用交易账户
→ Owner 明确确认一次
→ 后续受限 Session 交易尽量不重复弹钱包
```

当前实现仍坚持权限边界：交易账户和 Session 只用于 OddLane 受限操作；提现、任意授权和任意外部调用不能因为“快速交易”而放宽。

Passkey 目前仍是受限权限验证与实验能力，不作为买卖主路径的前置条件。

## Demo 主路径修复与体验收敛

这次更新重点修复和收敛了几个演示风险：

```text
领取的 Test USDC 进入交易账户
→ 再存入订单簿成为可用现金
```

充值校验与页面文案已对齐交易账户余额，不再把 EOA 钱包余额误当成入金来源。领水、充值、启用或关闭快速交易等关键动作补充了可见 Toast 与失败提示，降低现场出现“点击后没有反馈”的排障成本。

快速交易的 Gas 边界也被明确：当前 Monad 上的 Session 交易由交易账户自付 MON Gas，不依赖 Session Paymaster。缺少 MON 时应给出明确提示，并可关闭快速交易回退到 Owner 确认路径。
