# 2026-07-25｜Week 3 Day 6：验证 Pyth BTC/USD 在 Monad Testnet 的真实链上更新

## 今日目标

昨天调研 15 分钟 BTC/USD 涨跌预测方向时，我发现 Monad 文档中列出的 Chainlink Testnet Price Feed 地址当前没有 bytecode，不能直接把它当成可用结算来源。

所以今天不继续停留在文档层，而是验证 Pyth Pull Oracle 是否能在 Monad Testnet 上跑通：拿到签名价格更新、在链上验证、读取新鲜价格，并留下公开交易证据。

## 今天完成了什么

### 1. 确认 Pyth 的 Pull Oracle 实际工作方式

Pyth 的 BTC/USD 更新数据可以从 Hermes 获取，但链上不会自动刷新。直接读取 Monad Testnet 上 Pyth 合约缓存的 BTC/USD 时，拿到的是一份很旧的价格。

因此正确路径不是只读 `getPriceUnsafe`，而是：

```text
Pyth Hermes 签名更新
→ 调用 updatePriceFeeds
→ Pyth 在链上验证
→ 读取有 freshness 限制的价格
→ 应用合约记录结果
```

这也是 15 分钟预测市场能否公平结算的关键：每个 Round 的开盘价和结算价都必须来自对应时间窗内的新鲜验证数据。

### 2. 部署最小 Pyth BTC/USD Probe

我部署了一个最小的 `PythBtcPriceProbe`，它不做下注或奖池，只验证 Oracle 这一层：

- 查询本次 Pyth update 的精确 fee；
- 拒绝多付或少付；
- 将 `updateData` 交给 Pyth 验证；
- 使用 `getPriceNoOlderThan` 读取 60 秒内的新鲜 BTC/USD；
- 记录价格、置信区间、指数与 `publishTime`；
- 价格为零或负数时拒绝。

### 3. 跑通真实 Testnet 更新

今天已在 Monad Testnet 广播并成功确认两笔交易：

- [部署 PythBtcPriceProbe](https://testnet.monadvision.com/tx/0x5799612718547ce114d7e0c9fbff4725344625ee608b573ebb16d4fd41e1829b)
- [提交 Pyth 更新并记录 BTC/USD](https://testnet.monadvision.com/tx/0xcaca6f5f1ae8b4f30ce22f62fcee66f57512aa509c5444ed5b824eefc1f2e7c0)

```text

```

这不是前端显示的行情，也不是服务端代填的数字；价格更新由 Pyth 验证后才被 Probe 写入链上。

## 今天的收获

预言机接入不能只看“文档里是否列了一个地址”。对于短周期预测，至少要同时确认：

```text
目标链上是否真的有合约代码
→ 价格是否能在目标时间窗内刷新
→ 更新是否可以被链上验证
→ publishTime 是否足够新
→ confidence 是否在可接受范围
```

Pyth 的 Pull 模式需要结算者主动带着签名 update 发交易，但好处是新鲜度可以由合约明确检查，而不是依赖一个不保证每 15 分钟更新的 Push Feed。
